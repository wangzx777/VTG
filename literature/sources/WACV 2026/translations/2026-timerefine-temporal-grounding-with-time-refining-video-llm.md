# TIMEREFINE：使用时间细化视频大语言模型进行时序定位

## 摘要

视频时序定位旨在根据文本提示，在视频中定位相关的时间边界。近期工作致力于让视频大语言模型通过时间戳的下一词元预测来执行视频时序定位。然而，当仅依赖时间词元预测时，视频大语言模型仍然难以准确定位视频中的时间戳。我们提出的 TIMEREFINE 从两个方面解决这一挑战。首先，我们不直接预测起止时间戳，而是将时序定位重新表述为时间细化任务：模型先做出粗略预测，再通过预测目标片段的偏移量进行修正。该细化过程重复多次，使模型逐步提高自身的时间定位精度。其次，为增强模型的时间感知能力，我们加入一个辅助预测头；预测片段偏离真实片段越远，该预测头施加的惩罚越大，从而鼓励更精确的时间定位。我们的即插即用方法可以集成到大多数基于 LLM 的时序定位方法中。实验结果表明，TIMEREFINE 在 ActivityNet 和 Charades-STA 数据集上分别带来 3.6% 和 5.0% 的 mIoU 提升。代码和预训练模型可在 https://github.com/SJTUwxz/TimeRefine_code 获取。

## 1. 引言

视频时序定位（VTG）[5, 8, 9, 17, 28, 38, 39, 74–76, 83, 84, 86, 88, 90] 是视频理解中的基础任务，目标是根据文本提示定位视频中的时间边界，例如“这个人在什么时候搅拌汤？”。VTG 有大量现实应用，包括异常检测 [73]、体育分析、监控、消费级视频检索和教育。

大语言模型（LLM）[3, 12, 30, 51, 60, 69, 78] 擅长以零样本方式进行文本理解与生成。近期研究将 LLM 扩展到视频，视频大语言模型 [7, 10, 20, 24, 32, 33, 36, 40, 43, 48, 54] 已被用于字幕生成 [26, 34, 47, 57, 58, 63, 87] 和问答 [27, 34, 64, 70–72, 74] 等任务。然而，它们执行时序定位的能力仍然有限，因为多数预训练数据强调内容，即“是什么”，而不是时间感知，即“何时”[24]。

为增强视频大语言模型的时间感知能力，现有大多数工作 [20, 24, 54] 侧重构建高质量指令微调数据集，或修改架构以更好地将视觉特征融入 LLM，并改进时间词元的编码。然而，涉及时间戳回归的时序定位任务与 LLM 使用的传统文本预测任务很不相同。因此，仅改进模型架构可能不足以让 LLM 有效执行时序定位。

本文不改变模型架构，而是通过修改学习目标，从新的角度增强视频大语言模型执行时序定位的能力。与其他直接为给定查询预测起止时间戳的视频大语言模型不同，例如直接给出“18.6 秒至 23.8 秒”，我们将时序定位重新表述为渐进式时间细化任务。模型首先预测粗略时间戳，例如“15.0 秒至 27.5 秒”，随后预测到最终目标片段的偏移量，例如“+4.0 秒和 -1.5 秒”，以细化结果。我们应用多个这样的细化步骤，鼓励模型自行纠正先前预测中的错误。

除了时间细化过程，我们还发现，用标准交叉熵（CE）损失 [19] 预测时间戳并非最优。例如，当真实时间戳为“20 秒”时，CE 损失会对“21 秒”和“100 秒”的预测施加相同惩罚，尽管后者显然更不准确。为了有效学习时间边界，预测离真实值越远，模型就应受到越大惩罚。为此，我们在下一词元预测头之外增加一个采用 L1 损失的辅助预测头，使惩罚与预测到真实值的距离成正比。这样模型可以学会更偏好接近真实值的预测，从而得到更准确的时间定位。

TIMEREFINE 可以方便地应用于任何基于 LLM 的时序定位方法。实验表明，将该方法集成到 VTimeLLM [24] 后，在 ActivityNet Captions [26] 与 Charades-STA [16] 上分别带来 3.6% 和 5.0% 的 mIoU 提升；应用于 VTG-LLM [20] 时，在 Charades-STA 上获得 1.2% 的 mIoU 提升。

## 2. 相关工作

视频大语言模型。近期研究 [32, 36, 65, 67, 81, 85] 致力于增强基于图像的 LLM [31, 40] 的视频理解能力，并在视频问答和视频字幕等许多视频理解任务上取得了出色结果。然而，这些方法通常难以完成更细致的时间理解 [41]。多数方法关注高质量指令微调数据集或架构修改，而我们则着重修改学习目标，使视频大语言模型框架更适合时序定位。

视频时序定位。视频时序定位（VTG）旨在准确识别视频中的事件时间戳 [37]，是视频理解的关键任务。传统的任务专用模型 [29, 44, 45, 77, 80] 通常将它表述为基于视频输入和用户查询的时间戳回归任务。尽管早期取得成功，这类模型在零样本设置下表现欠佳，每个模型只能处理单一任务，而且经常需要针对不同下游任务和数据集额外微调。

近期方法 [21, 24, 25, 35, 48, 49, 62, 66, 79] 利用强大的视频大语言模型执行时序定位。例如，VTimeLLM [24] 直接在 VTG 数据集上微调视频大语言模型；LITA [25] 将 SlowFast 视觉词元和时间词元加入 LLM 词元表，以增强时间定位能力；Momentor [48] 使用时间编码器处理时间词元量化误差，改进细粒度时间推理；VTG-LLM [20] 集成专用时间词元和时间位置嵌入，增强视频大语言模型对时间戳的理解。然而，这些方法主要强调数据收集或视觉、时间特征的新编码机制，经常忽视视频大语言模型执行时序定位时的根本挑战。相比之下，TIMEREFINE 使用逐步细化技术，并为视频大语言模型提供更有效的训练目标。

基于细化的学习。先做出粗略预测，再逐步提高精度的细化思想由来已久，并已在计算机视觉中得到广泛探索。例如，两阶段目标检测器 [18, 22, 53] 使用区域候选网络生成候选框，再由另一个网络细化并产生最终预测；VideoGrounding-DINO [68] 在类似 DETR 的架构上训练时间预测头；迭代误差反馈也常用于人体姿态估计等需要逐步精确细化的任务 [4]；扩散模型 [11, 13, 23] 同样采用逐步去噪方法。与此同时，细化也被用于改善 LLM 的推理 [6, 46, 89]。受这些工作启发，TIMEREFINE 为时序定位提出一种细化范式，通过下一词元预测迭代地细化结果。据我们所知，TIMEREFINE 是首个探索将这种细化思想用于基于 LLM 的时间定位的工作。

## 3. 方法

### 3.1 问题定义

给定视频 $V\in\mathbb{R}^{T\times H\times W\times C}$ 和文本查询 $Q$，例如“视频中的男子什么时候吃早餐？”，模型需要生成带有定位时间戳的相应答案 $A$，例如“20 秒至 90 秒”。

现有方法 [20, 21, 24, 48, 54] 使用下一词元预测方案，将视频时序定位任务纳入视频大语言模型框架。在文本查询和视频输入条件下，预测答案的对数似然可表示为：

$$
l=\sum_{i=1}^{m}\log p(a_i\mid H_v,H_q,a_{j<i}),
\tag{1}
$$

其中，$H_v=\phi(V)$ 是由预训练视频编码器 $\phi$ 编码的视频词元，例如 CLIP [50]；$H_q=\{q_1,q_2,\ldots,q_n\}$ 是查询的词元化元素；$H_a=\{a_1,a_2,\ldots,a_m\}$ 是答案的词元化元素。时间戳的编码词元，例如“20 秒”，被称为时间词元，可以表示为标准文本词元，例如 VTimeLLM [24]，也可以表示为某些特殊词元，例如 VTG-LLM [20] 使用 `<TIME-TWO>`。

我们发现这种标准的基于视频大语言模型的时间定位框架存在两个关键问题。

第一，在长视频中直接预测时间戳十分困难。此外，在 LLM 框架中将时间戳预测视为词元预测会造成监督稀疏：模型处理数百个视觉和文本词元时，每个片段只能从两个时间词元获得监督，例如一个起点词元和一个终点词元。相比之下，ActionFormer [82]、TallFormer [9] 等传统时序定位模型会为每个输入回归数百个边界框，得到强得多的监督信号。

第二，下一词元预测所使用的交叉熵损失并不适合时间预测任务。对于时间戳“20 秒”，CE 会对“21 秒”和“100 秒”的预测施加相同惩罚，尽管前者准确得多。这使模型无法学会在时间任务中更偏好接近真实值的预测。

为解决这些问题，我们提出 TIMEREFINE，具体内容见下文。

### 3.2 TIMEREFINE

TIMEREFINE 为基于 LLM 的时序定位任务提出逐步细化范式。这种迭代细化策略帮助模型学会自行纠正边界感知错误，从而增强视频大语言模型的时间理解能力。

首先，我们将时间词元预测任务重新表述为迭代时间细化。给定视频和用户提示，模型需要执行多轮预测。每一轮先做出粗略预测，再学习自行纠正该预测中的错误。该方案不仅提供更强的监督信号，还将直接预测精确时间戳的问题转变为粗到细预测，类似人类在视频中定位时刻的方式。其次，我们引入辅助时间预测头，以增强视频大语言模型的时间感知能力。该辅助头使用 L1 损失优化，帮助模型学会在时序定位中更偏好接近真实值的预测。

### 3.2.1 架构

我们的方法不依赖具体模型架构，可以应用于任何遵循上述问题定义、基于 LLM 的 VTG 方法。一个常见的视频大语言模型架构由视觉编码器、视觉适配器、文本分词器和大语言模型组成。视觉编码器通常是用于提取视觉特征的类 CLIP 模型 [50]。视觉适配器使用 MLP [56] 或 Q-Former [31] 将视觉特征投影到语言空间。LLM 将视频的视觉嵌入和用户提示的嵌入文本词元作为输入并输出答案。我们保持核心架构不变，仅修改学习目标，加入时间片段的迭代细化和辅助片段预测头。

### 3.2.2 迭代时间细化

我们从两个方面修改直接时间戳预测方案。首先，视频大语言模型难以直接预测时间戳，因此我们采用粗到细方法：模型先生成粗略预测，再预测到目标片段的偏移量来修正结果，并由此学会自我纠错。其次，单步做出精确预测很困难，因此我们迭代应用这种粗到细策略。模型由此获得多次修正预测的机会，逐步提高时间定位精度。

对于以秒为单位、起止时间戳为 $S=(s,e)$ 的真实片段，我们将其转换为以下迭代时间细化预测序列：

$$
\mathcal{S}=((s_0,e_0,o_0^s,o_0^e),\ldots,(s_K,e_K,o_K^s,o_K^e)),
\tag{2}
$$

其中，$(s_0,e_0,o_0^s,o_0^e)$ 表示一个粗到细预测步骤，$s=s_k+o_k^s$、$e=e_k+o_k^e$，而 $o_k^s$ 和 $o_k^e$ 是到目标片段的偏移量。$K$ 表示细化步骤数。训练期间，我们使用额外控制词元将 $\mathcal{S}$ 格式化为序列：`<seg_start>`，$s_0$ 到 $e_0$，`<offset>`，$o_0^s$ 和 $o_0^e$；随后依次加入 `<refine>`、新的边界与偏移量，直至第 $K$ 步，最后以 `<seg_end>` 结束。

迭代时间细化方案要求模型学会三件事：根据用户输入做出粗略预测 $s_k$ 和 $e_k$；通过预测 $o_k^s$ 和 $o_k^e$ 自行纠正错误；依据先前细化步骤发起新的预测与细化。与现有视频大语言模型的直接时间戳预测相比，该方案提供强得多的监督信号，并使模型能够学习自我纠错，进一步提高时间预测精度。

训练序列生成。重新定义任务的关键之一是生成训练序列。受扩散模型 [13, 23] 启发，去噪过程逐步加入更少噪声以逼近真实值。我们定义 $K$ 个高斯分布 $\{\mathcal{N}_k(0,\sigma_k^2),k=1,\ldots,K\}$，其中 $\sigma_k$ 与 $K$ 是预定义参数。给定真实片段 $S=(s,e)$，从这些分布采样偏移量 $o_k^s$ 和 $o_k^e$：

$$
o_k^s\sim\mathcal{N}_k(0,\sigma_k^2),\qquad o_k^e\sim\mathcal{N}_k(0,\sigma_k^2),
\tag{3}
$$

$$
s_k=s-o_k^s,\qquad e_k=e-o_k^e.
\tag{4}
$$

如果细化步骤 $k$ 的 $s_k$ 或 $e_k$ 小于 0 或超过视频时长，则重新采样。给定视频词元 `<v1>` 至 `<vn>`，一个输入 LLM 的示例序列包括问题“男子什么时候吃早餐？”，随后答案从 `<seg_start>` 开始，依次给出粗略边界、`<offset>` 偏移量以及多轮 `<refine>` 边界与偏移量，直至偏移归零并以 `<seg_end>` 结束。

### 3.2.3 时间感知

基于 LLM 的视频时序定位方法广泛使用交叉熵损失 [19]，但它不太适合预测作为连续变量的时间戳。例如，当真实时间戳为 20 秒时，CE 对 $p(t=20s)=0.1,p(t=21s)=0.9$ 和 $p(t=20s)=0.1,p(t=100s)=0.9$ 施加相同惩罚，尽管后者明显更不准确。

为解决该问题，我们在 `<refine>` 词元上连接一个辅助预测头，用于预测片段起点和终点：

$$
\hat{S}=\operatorname{Linear}(h[\texttt{<refine>}]),
\tag{5}
$$

其中，$h[\texttt{<refine>}]$ 是模型最后一层中 `<refine>` 词元的嵌入。预测 $\hat{S}$ 由预测值与真实值之间的 L1 损失监督，即 $L_1=|\hat{S}-S|$。不同于交叉熵损失，预测离真实值越远，L1 损失施加的惩罚越大，从而增强模型的时间感知能力。为保持视频大语言模型的完整性，我们保留原始交叉熵损失，并将 L1 损失作为辅助监督信号。我们也尝试了 GIoU [55] 等其他损失函数，但没有观察到提升。

### 3.3 训练与推理

训练。遵循视觉语言模型的做法，我们使用下一词元预测训练模型，并且仅在答案部分计算损失。总损失结合原始交叉熵损失与辅助线性分支的 L1 损失：

$$
L=\frac{1}{m}\sum_{i=1}^{m}\operatorname{cross\_entropy}(\hat{a}_i,a_i)+\lambda\frac{1}{2|S|}|\hat{S}-S|,
\tag{6}
$$

其中，$\hat{a}_i$ 和 $a_i$ 分别是预测答案词元与真实答案词元，包括时间词元；$|S|$ 是答案中的片段数量；$\lambda$ 是平衡两项损失的超参数。

推理。答案生成过程遵循视频大语言模型的下一词元预测方案。推理时丢弃辅助预测头。预测时间片段 $S$ 时，使用最后一个细化步骤的 $s_K+o_K^s$ 和 $e_K+o_K^e$ 作为起止时间戳。

### 3.4 实现细节

TIMEREFINE 与架构无关，可以应用于大多数基于 LLM 的 VTG 方法。下面先介绍 TIMEREFINE 的超参数，再说明如何将其用于 VTimeLLM [24] 和 VTG-LLM [20]。

### 3.4.1 TIMEREFINE

迭代时间细化方案。我们重新格式化训练数据，将定位相关问答对中的直接起止时间戳替换为时间细化序列，同时保持非定位问答对不变。构建迭代时间细化序列时，每个时间片段的细化步数设为 $K=4$。$K$ 个高斯分布使用按递减顺序排列的固定标准差 $\sigma^2=\{5,3,1,0\}$ 秒。该设计在细化过程中逐步减少加入的噪声以逼近真实值，从而模拟粗到细的细化过程。

时间感知。除交叉熵损失外，我们加入权重为 $\lambda=10$ 的 L1 损失以平衡两项损失。

### 3.4.2 与其他 VTG 方法集成

VTimeLLM。为与 VTimeLLM [24] 直接比较，我们使用与其相同的训练设置和数据。TIMEREFINE 从 VTimeLLM 第一阶段检查点初始化，此时视觉特征已经与 LLM 语义空间对齐。随后分别在第二阶段和第三阶段训练数据上训练 4000 步与 1000 步，学习率为 $1\times10^{-4}$，使用一台配有 8 张 A5000 24G GPU 的机器。LoRA rank 设为 64，alpha 设为 128。

VTG-LLM。我们也将 TIMEREFINE 应用于 VTG-LLM，并使用与原始 VTG-LLM 相同的训练数据，即 VTG-IT-120k [20] 和从 Valley 数据集 [42] 随机采样的 97k 子集。批大小、学习率、优化器等所有超参数均保持与原始 VTG-LLM 一致。

## 4. 实验

### 4.1 评估设置

评估数据集。遵循先前工作 [20, 24]，我们使用 ActivityNet Captions [26] 与 Charades-STA [16] 作为评估数据集，测量预测时间片段与真实片段之间的交并比，并报告 IoU 阈值 0.3、0.5、0.7 下的 Recall@1 和平均 IoU。尽管不是本文重点，我们还在 ActivityNet Captions 上评估密集字幕任务，使用 SODA_c [15] 评估故事线一致性，CIDEr [61] 评估字幕质量，并使用在不同 IoU 阈值上取平均的 METEOR [1] 衡量时间定位准确性。

基线。除 VTimeLLM 与 VTG-LLM 外，我们还与两类视频大语言模型比较：VideoChat-7B [32]、VideoLLaMA-7B [85]、VideoChatGPT-7B [43] 和 Valley-7B [42] 等传统视频大语言模型；以及 GroundingGPT [35]、TimeChat [54]、Momentor [48] 和 HawkEye [66] 等专为 VTG 设计的视频大语言模型。

### 4.2 主要结果

我们将 TIMEREFINE 应用于 VTimeLLM [24]，并在 ActivityNet Captions [26] 与 Charades-STA [16] 上评估。在训练设置与数据完全相同的情况下，它在 ActivityNet Captions 上比 VTimeLLM-7B 的 R@0.7 高 3.2%，mIoU 高 3.6%。尽管不是本文目的，密集视频字幕任务也获得小幅提升，说明该方法不仅改善时序定位，也有益于其他定位相关任务。

我们还与现有视频大语言模型比较。由于这些模型在不同数据集上训练，直接比较较为困难。尽管如此，在 ActivityNet Captions 与 Charades-STA 上，TIMEREFINE 在所有 7B 视频大语言模型中的多数指标上取得最佳性能。与 RTX A5000 上的 VTimeLLM 相比，该方法仅引入很小计算开销：每次训练迭代耗时由 7.1 秒变为 7.23 秒，每个问题的推理耗时由 2.0 秒变为 2.3 秒。与视频特征提取及 LLM 处理其他所有词元的开销相比，额外时间词元带来的开销可以忽略。

为展示 TIMEREFINE 对不同视频大语言模型的即插即用适应性，我们还将它应用于 VTG-LLM [20]。在 Charades-STA 的零样本时序定位上，TIMEREFINE 的 R@0.3、R@0.5 和 R@0.7 分别比 VTG-LLM 高 4.6%、1.3% 和 1.0%。VTG-LLM 通过整合时间戳知识提高时序定位精度，而 TIMEREFINE 借助迭代时间细化与辅助时间监督进一步增强这种能力。

### 4.3 定性评估

在 Charades-STA 的零样本设置中，VTimeLLM [24] 与 VTG-LLM [20] 直接预测一个片段，IoU 分别为 0.46 与 0.65。相比之下，VTimeLLM-TIMEREFINE 先估计 IoU 为 0.46 的粗略片段边界，再通过额外三个细化步骤逐步修正；每一步都会生成新片段和偏移量。最终预测的 IoU 达到最高的 0.95，体现了迭代时间细化与辅助监督的有效性。

### 4.4 设计选择

本节考察 TIMEREFINE 的设计选择，并详细消融迭代时间细化策略和用于时间感知的辅助预测头。除非另有说明，所有结果均来自在 ActivityNet Captions 时序定位任务上对基于 VTimeLLM-7B [24] 的 TIMEREFINE 进行评估。

### 4.4.1 时间细化任务设计

第一个问题是如何设计有助于视频大语言模型更好地学习时序定位的细化任务。我们考察三种方案。

无细化。模型直接预测起止时间戳，例如“10 秒至 20 秒”。

IoU 预测。模型先预测时间戳，再预测该结果与真实片段之间的 IoU，例如“10 秒至 20 秒，IoU 为 0.6；11 秒至 18 秒，IoU 为 0.9”。模型可以在自我纠错过程中利用这种反馈。

偏移量预测。模型先预测时间戳，再为每个时间戳预测相对于目标的偏移量，例如“10 秒至 20 秒，偏移量为 +2 秒和 -3 秒；12 秒至 17 秒，偏移量为 0 秒和 0 秒”。这种信息为如何细化预测提供额外指导，有益于自我纠错。

我们使用标准差为 5 秒的高斯噪声生成 IoU 预测和偏移量预测的训练样本。两种方法都优于无细化变体，说明要求模型更充分地考虑自己的预测会带来收益，类似“思维链”概念。偏移量预测表现最佳，mIoU 比无细化方法高 1.1%。我们推测，这是因为偏移量预测比 IoU 预测提供更直接、更清晰的监督。因此，其他实验均使用偏移量预测。

### 4.4.2 细化序列生成策略

模型需要多少个细化步骤 $K$？我们将 $K$ 从 2 变到 8，考察其对时间预测性能的影响。使用 4 步带来最大提升，继续增加后性能趋于饱和。这说明预测并细化多个时间片段有益于时序定位。

模型需要多少噪声？对于 $K=4$ 个固定标准差高斯分布，我们调整噪声量。从 $\{5,3,1,0\}$ 出发，分别按 0.4、1、2 和 4 倍改变噪声。结果表明，较小噪声更有效，较大噪声会扰乱模型学习。

噪声是否需要随视频时长自适应？我们将标准差设为视频长度的比例，让较长视频加入更强噪声。使用 $\{0.2,0.1,0.05,0\}$ 和 $\{0.1,0.05,0.01,0\}$ 两组自适应标准差，其中每个数值表示视频时长的一部分。与固定标准差相比，自适应标准差使 mIoU 降低 0.6%。这一结果是合理的，因为视频中的时间动态与其总长度无关，短视频和长视频应采用一致的噪声分布。其他实验均采用 $K=4$ 和标准差 $\{5,3,1,0\}$。

### 4.4.3 时间感知

辅助预测分支是否有助于时间感知？加入使用 L1 损失优化的辅助分支后，mIoU 比无辅助损失高 1.6%。这表明辅助监督信号可以补充原始交叉熵损失，进一步增强模型的时间感知能力。

哪种损失最有助于时间预测？除交叉熵损失外，我们尝试用 L1、L2 和 GIoU 损失作为辅助监督，因为这些损失常用于检测和定位任务 [2, 52, 53, 55, 59, 91]。实验表明 L1 损失最有效，进一步加入 GIoU 并没有带来明显提升。

### 4.4.4 片段解码

每次细化过程包含多个步骤，因此可以选择初始步骤或最终步骤预测的片段；也可以使用辅助头预测的片段，或将其与基于序列的预测结合。结果显示，最终步骤预测的片段显著优于初始步骤，这与序列细化设计一致，因为最终片段本来就应匹配目标；使用辅助预测头、最后一步序列预测或二者组合的性能相近。这意味着训练结束后可以丢弃辅助头，使该方法与现有词元生成框架兼容。

## 5. 结论

本文提出 TIMEREFINE，以增强视频大语言模型的时序定位能力。不同于侧重数据整理或架构增强的先前方法，我们改进学习目标，使视频大语言模型框架更适合时序定位。我们将时间戳预测任务转换为迭代误差细化任务，并在下一词元预测之外加入辅助 L1 预测头，鼓励模型做出更接近真实值、更准确的预测。该方法与架构无关，可以应用于任何视频大语言模型，并以很小的额外训练开销带来可观性能提升。一项局限是，与先前方法相比，需要预测数倍的时间相关词元。不过，当用户同时关心时序定位和问答任务时，这一缺点得到缓解，因为模型生成的文本词元数量远多于时间词元。未来研究方向包括进一步改进任务与序列设计，并探索时序定位如何增强视频问答。
