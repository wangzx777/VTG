# VTG Research Workspace

## Purpose

Research workspace for Video Temporal Grounding / Video Temporal Retrieval.

## Structure

- `literature/sources/`: original paper PDFs grouped by venue/year; each group may
  contain `translations/` and `notes/` generated by `paper-read`
- `literature/extracted/`: text extracted from papers for efficient AI reading
- `literature/papers.xlsx`: paper index and cross-paper summary
- `repos/`: official/reference implementations
- `project/`: user-owned research code
- `.agents/skills/`: reusable research workflows

## Research Assets

- PDFs are the source of truth for paper claims.
- `extracted/` is a reading cache derived from PDFs; prefer it for text retrieval, but verify ambiguous, missing, visual, tabular, or equation-heavy content against the PDF.
- Venue-local `sources/<venue-year>/notes/` contains concise AI reading notes,
  and `sources/<venue-year>/translations/` contains paragraph-aligned Chinese
  translations. Reuse them before repeating the work.
- Repository code is the source of truth for implementation claims.

## Research Artifacts

- Reuse existing derived artifacts before repeating work.
- Prefer the venue-local `notes/` beside a source PDF for current paper-reading
  output.
- Prefer `literature/extracted/` when detailed paper text is needed.
- Use `literature/sources/` to verify figures, tables, equations, ambiguous extraction, or original claims.
- Verify implementation details directly against the pinned repository revision in
  `repos/`; record user-owned implementation work in `project/`.

## Working Rules

- Never invent missing paper facts, code paths, functions, configs, or results. Use `N/A` or mark them unverified.
- Do not repeat completed extraction, paper analysis, or code tracing when valid derived artifacts already exist; reuse them and consult source material only as needed.
- Keep `papers.xlsx` concise; current translations and reading notes belong in
  the venue-local `translations/` and `notes/` directories.
- Treat `repos/` as read-only unless explicitly asked to modify it.
- Only modify `project/` for user-owned research implementation or experiments.
- Preserve the workspace structure unless the task explicitly requires a change.

## Git Synchronization

- `origin/main` stores the complete reusable workspace: `.agents/`, `literature/`,
  `project/`, `repos/`, and `Log/`. Runtime environments, datasets, checkpoints,
  and experiment outputs are excluded by `.gitignore`.
- Both the Mac and the 4090 host use a complete checkout. Git pulls commits, not
  selected directories; do not use folder-only synchronization for `project/` or
  `repos/`.
- Before editing on either host, require a clean worktree and run
  `git pull --rebase origin main`. After a verified task, commit the intended paths
  and push `main` so the other host can pull them.
- The 4090 host normally changes only `project/` and `repos/`. It still pulls the
  complete repository before work so that current paper caches, notes, and skills
  are available locally.
- Add official/reference repositories under `repos/` as Git submodules when
  practical. Push changes inside a submodule to a writable upstream or fork first,
  then commit the updated submodule revision in this repository.

## Workspace Change Log

- After every task that creates, modifies, moves, or deletes files inside this
  workspace, append one concise entry to `Log/<ISO-year>-W<ISO-week>.md`.
- When Codex operates the 4090 host remotely, record the task in the Mac checkout
  at `/Users/macchiato/VTG/Log/`; do not modify the remote checkout only to add a
  log entry.
- Use the Asia/Shanghai local timestamp format `YYYY-MM-DD HH:mm:ss CST`. ISO
  weeks run from Monday through Sunday; for example, `Log/2026-W34.md`.
- Record the user task, affected workspace-relative paths, and a brief statement
  of what changed. For deletions or moves, also record the recovery location
  when one exists.
- Write log entries in Chinese unless the user explicitly requests another
  language. Keep filenames, paths, commands, and technical identifiers unchanged.
- Append after implementation and verification. Never rewrite or delete earlier
  entries; record corrections or rollbacks as new entries.
- Do not create an entry for read-only inspection or explanation tasks.
- Do not recursively list the routine append to the weekly log itself as an
  affected-file change. Do record changes to this logging policy.
- Never put secrets, credentials, private keys, tokens, or unnecessarily large
  diffs in the log.
